# 配置指南 · Job Hunt Workbench

> 这份指南面向**第一次接手这套工作台的人**：告诉你每个配置文件里有什么、哪些必须改、改错了会发生什么。
> 配合 [`README.md`](../README.md)（快速开始）和 [`docs/工作台设计.md`](工作台设计.md)（架构与接口契约）一起看。

---

## 0. 先建立心智模型

这套系统把求职流程拆成五段：**岗位判断 → 市场调研 → 简历定制 → 投递 → 跟踪与回复**。
配置只回答三件事：

| 问题 | 由谁回答 |
|---|---|
| 数据文件叫什么、在哪 | `config/local/app.json` 的 `files` / `sources` / `cleanup` |
| 侧栏长什么样、每段打开哪一页 | `config/local/routes.json` |
| 有哪些渠道、CSV 列怎么排 | `config/local/channels.json` |

其余配置都是「可选增强」，缺了不致命。但 `app` / `routes` / `channels` / `identity` 四份**缺任何一份，服务直接退出**（刻意不静默兜底——默认文件名猜错会把数据写到别处）。

### 加载优先级

```
config/local/<name>.json     ← 你的值（整目录 gitignored，永不提交）
        ↑ 不存在时
config/<name>.example.json   ← 通用骨架（全是 <占位符>，启动会报缺项）
```

规则同理：`rules/local/` > `rules/*.example.json`。

### 数据模型（重要，先看懂再配）

系统里有两份**互不相同**的数据，别混淆：

| 数据 | 文件 | 谁写 | 语义 |
|---|---|---|---|
| 跟踪台账 | `app.files.data`（如 `unified_data.json`） | **主应用**（增删改） | 有沟通、有后续机会的重点记录，随进度改状态 |
| 投递事件流 | `runs/<run_id>/ledger.jsonl` | 采集/投递脚本（append-only） | 海投流水，每行一条 JSON，只增不改 |

工作台首页的「台账事件」「已投递」两个数字、以及「投递」段的台账页，读的是**投递事件流**；
「跟踪与回复」段的主应用读写的是**跟踪台账**。demo 里两份都给了示例数据，跑起来就能看到区别。

## 1. `config/local/app.json` —— 运行参数（必配）

### 1.1 `files`（五项全必需）

```json
"files": {
  "data": "unified_data.json",        // 跟踪台账数据文件（主应用读写）
  "backup": "unified_data.backup.json",// 写入前的自动备份
  "csv_main": "台账.csv",              // 主 CSV 导出名
  "csv_campus": "校招台账.csv",        // 校招 CSV 导出名
  "app_html": "求职台账.html",         // 主应用页面名（app/build.js 的输出）
  "rules_fallback": "rules/local/job_family.json"  // 岗位族规则回退（可选）
}
```

- **缺任何一项，`node server.js` 打印缺哪个键并 `exit 2`**。这是刻意的：如果静默用默认文件名，一旦和你真实文件不一致，写入会落到错误的地方。
- `app_html` 同时是 `app/build.js` 生成页面的文件名，两边要一致。

### 1.2 `pages` —— 页面路由

```json
"pages": {
  "workbench": "工作台.html",          // 工作台壳文件名
  "workbench_paths": ["/workbench"],  // 壳的别名地址
  "home_paths": ["/", "/index.html"]  // 主应用页的别名地址（旧书签继续可用）
}
```

### 1.3 `build` —— 主应用页面生成

```json
"build": { "template_dir": "app", "template": "app.template.html" }
```

`app/build.js` 读取这份配置，把模板 + 数据 + 渠道注入，生成 `files.app_html`。改完模板或数据后跑一次 `node app/build.js`。

### 1.4 `cleanup` —— 台账清理的数据来源

```json
"cleanup": {
  "out_dir": "runs/cleanup",          // 清理输出（备份、删除清单）目录
  "scan_dir": null,                   // 扫描产物根目录；null 则跳过「回填」，只做判定
  "scan_files": [                     // 扫描产物 → 索引
    { "file": "x.json", "tag": "平台A投递", "role": "jobs" },       // 建岗位/薪资索引
    { "file": "y.json", "tag": "平台B投递", "role": "jobs_alt" },   // 备用岗位索引
    { "file": "delta.json", "tag": "会话", "role": "delta" }        // 会话列表快照
  ],
  "detail_files": ["details.json"]    // 逐条展开过的会话明细
}
```

`role` 是本段的「换平台只改这里」关键：`jobs` / `jobs_alt` / `delta` 三种角色决定了脚本怎么用这个文件。整段缺失时跳过回填、只做判定，不报错。

### 1.5 `sources` —— 工作台只读数据源

```json
"sources": {
  "job_families": "demo_data/metrics.example.json",   // 岗位族匹配数据
  "resume_versions": "demo_data/resume_versions.example.json", // 简历版本映射
  "atlas_deep_link": "",                              // 图谱深链前缀（可空）
  "doc_roots": ["docs"],                              // Markdown 白名单根目录
  "doc_allow": ["工作台设计.md"]                       // 允许打开的文档
}
```

缺失时对应接口返回 `SOURCE_MISSING`，页面**显式提示**，不猜、不静默兜底。

### 1.6 `artifact_scans` —— 产物自动发现（核心能力）

```json
"artifact_scans": [
  {
    "group": "resume",                 // 挂到 routes.json 的哪个段
    "pattern": "简历_*.html",           // 同层通配（* 只匹配一层，禁止 .. 与绝对路径）
    "label_from": "basename",          // basename=去扩展名；dirname=取父目录名
    "strip_prefix": "简历_",            // 标签里去掉的前缀
    "exclude": ["简历_母版.html"],       // 排除项
    "sort": "name",                    // name / mtime_desc / mtime_asc
    "badge": "版本",                    // 角标文字
    "note": "新增简历自动出现在视图切换里"
  }
]
```

丢一个 `简历_<岗位>.html` 进去，刷新工作台，它会自动出现在「简历定制」段的视图条上。**新增数据不改代码**，靠的就是这段。

## 2. `config/local/routes.json` —— 导航形状（必配）

### 2.1 `groups` —— 侧栏分段

```json
"groups": [
  { "id": "home", "label": "首页", "order": 0, "kind": "link", "url": "工作台-首页.html" },
  { "id": "judge", "label": "岗位判断", "index": "①", "order": 1,
    "flow": "输入：… ｜ 输出：… ｜ 下一步：…" }
]
```

- `kind: "link"` 只有首页用（点击直接跳页面，不进 iframe）。
- `index` 是侧栏序号（①②③…）；`flow` 是首页卡片上的「输入/输出/下一步」三段（用全角 `｜` 分隔，`输入：`/`输出：`/`下一步：` 三个前缀解析）。
- **段数不一定是 5**：首页卡片用 flex 布局，加一段减一段都能自适应。

### 2.2 `items` —— 每段的入口与产物

```json
"items": [
  { "id": "judge_matrix", "label": "岗位族匹配判断", "group": "judge",
    "role": "primary", "url": "工作台-岗位判断.html", "order": 0,
    "note": "分档筛选 / 排序 / 展开明细" },
  { "id": "track_app", "label": "求职台账", "group": "track",
    "role": "primary", "url": "求职台账.html",
    "writable": true, "badge": "可写", "badge_kind": "write" }
]
```

关键字段：

| 字段 | 含义 |
|---|---|
| `role: "primary"` | 这段在**侧栏**显示的那一个入口（每段一个） |
| `variants[]` | 这段在**视图条**上显示的其余产物（报告、原文、母版等） |
| `writable: true` | 面包屑旁显示黄色「可写」徽标，标明哪一页会改你的数据 |
| `url` | 项目根相对路径；指向文档用 `工作台-文档.html?src=<file>.md` |

> 侧栏永远只渲染 `role: primary` 那一项 + 首页，共 6 行；**产物是运行结果，不是导航结构**，所以报告、简历、快照都放在 `variants` 里，或交给 `artifact_scans` 自动扫。

## 3. `config/local/channels.json` —— 渠道单一源（必配）

```json
{
  "channels": [
    { "key": "campus", "label": "校招", "type": "campus", "csv_label": "校招",
      "type_label": "校招", "order": 1, "enabled": true,
      "prob": { "add": 0, "why": "校招流程更规范，回复快" } },
    { "key": "platform_a", "label": "平台A", "type": "platform", "platform": "platform_a",
      "csv_label": "平台A", "type_label": "社招", "order": 2, "enabled": true,
      "prob": { "add": 0, "why": "看岗位匹配度" } }
  ],
  "csv_order": ["campus", "platform_a", "platform_b"],
  "labels": { "app_title": "求职台账", "workbench_title": "求职工作台", "csv_main_header": "来源" }
}
```

| 字段 | 含义 |
|---|---|
| `key` | 数据文件顶层键 + 表格分组的依据，**全局唯一、别改历史** |
| `type` | `campus`（校招）/ `platform`（平台）/ `custom`（自定义）——替代针对具体渠道的特判 |
| `csv_label` | CSV 列名；`csv_order` 显式声明列顺序，留空则按 `order` |
| `prob` | 概率引擎的渠道加分与文案（见 §6） |
| `labels.app_title` | 主应用标题（也决定「备份导出」的文件名前缀等） |

这一处改动会同时驱动：服务端分组、CSV 列顺序、主应用筛选下拉、渠道标签颜色（四色轮转）、概率引擎文案。

## 4. `config/local/identity.json` —— 身份事实源

```json
{
  "name": "你的名字", "graduation": "2026", "school": "你的学校",
  "city": "你的城市", "contact": "你的联系方式", "greeting": "招呼语",
  "tech_stack": ["TypeScript", "Python"]
}
```

真实值只在 `config/local/identity.json`（gitignored）。它是任务指令模板里「我是谁」的来源，不是硬编码进页面的。

## 5. `config/local/workbuddy.json` —— 任务指令接口位

```json
{
  "adapter": "clipboard", "adapter_slots": ["command", "webhook", "mcp"],
  "output_root": "workbuddy_out", "tasks_ref": "templates/workbuddy/tasks",
  "ai_disabled_hint": "页面内 AI 已停用，请在 WorkBuddy 会话中执行分析",
  "result_dirs": { "analysis": "analysis", "outreach": "outreach", "…": "…" }
}
```

机制固定（剪贴板 + 相对输出路径 + 只读结果列举），内容全由 `templates/workbuddy/tasks/*.md` 驱动。工作台右上「任务指令」面板复制的就是这些模板。

## 6. 其余配置（可选）

| 文件 | 作用 | 必配 |
|---|---|---|
| `config/local/conditions.json` | 投递条件（查询词、城市码、学历/年限、薪资下限、投递限额） | 否 |
| `config/local/conditions/<slug>.json` | **多方向条件**：一份一个求职方向（`family_id` + `profile_ref` + 本族差异） | 否 |
| `config/local/profile.json` | **唯一画像**：城市 / 学历 / 年限 / 技术栈 / 期望薪，多份条件共用 | 否 |
| `config/local/families.json` | **族 id 契约**：`id` → 市场数据键 / 条件 slug / 简历文件 / 判分词表 | 否 |
| `config/local/jobs.json` | **任务总线**扩展：追加自定义任务类型（argv 模板 + 超时） | 否 |
| `config/local/resume_versions.json` | 简历版本索引（只记路径与标签，不移动/改写简历） | 否 |
| `rules/local/job_family.json` | 岗位族分类：`rules` 关键词 → 族名，`preferred`/`low` 分档 | 否（缺则空规则集） |
| `rules/local/cleanup.json` | 清理口径：结束状态、活跃阶段、加权阈值 | 否（缺则用 example 中性默认） |
| `rules/local/prob.json` | 概率引擎：`base_score` 基础分、`regex` 关键词、`weights` 加权、`levels` 阶段 | 否（缺则用 example 中性默认） |

> `conditions.json` 里的 `city` / `city_code` 缺失时**显式报错**，绝不静默继承默认值——城市码一旦猜错，投递会投到错误的地域。

### 6.1 多方向条件 + 唯一画像（推荐结构）

一个求职者通常同时投几个方向。正确做法是**画像只写一份，条件只写差异**：

```jsonc
// config/local/profile.json —— 唯一真相
{
  "identity": {"city": "你的城市", "city_code": {"boss": "<BOSS城市码>", "zhilian": "<智联城市码>"},
                "education": "本科", "graduation": "2026"},
  "conditions_profile": {"education": "本科", "exp_years": 0, "exp_ceiling_years": 3,
                          "salary_floor": 7000, "allow_intern": false,
                          "tech_stack": ["Vue3", "React", "…"]},
  "target_filters": {"boss": {"求职类型": "全职", "学历要求": "本科"},
                      "zhilian": {"学历要求": "本科"}}
}
```

```jsonc
// config/local/conditions/it-support.json —— 只写这一个方向不同的地方
{
  "id": "cond-it-support",
  "family_id": "it-support",      // 指向 families.json
  "profile_ref": "profile",        // 指向 profile.json，共性字段全部继承
  "queries": ["IT技术支持", "IT运维工程师"],
  "profile_overrides": {"salary_floor": 7000},   // 覆盖画像里的值
  "deliver": {"min_grade": "B", "daily_limit": 100, "budget_min": 40, "pages_per_query": 2}
}
```

合并顺序：`profile.json` → 条件里的 `profile` → `profile_overrides`。
**有 `profile_ref` 但读不到画像文件时直接报错**，不会静默兜底——否则等于拿别人的画像投自己的岗。

`families.json` 把三套命名打通（缺了它就只能靠人脑对）：

```jsonc
{"families": {"it-support": {"label": "IT技术支持", "metrics_key": "IT技术支持",
                              "conditions": "cond-it-support", "resume": "f11",
                              "score_family": "tech_support", "active": true, "order": 1}}}
```

`score_family` 指判分时实际走的词表（`product` / `tech_support` / `project_mgmt` / `delivery` / `junior`），
它和展示用的 `id` 是两套命名，必须显式写。

### 6.2 任务总线（可选，但推荐）

`server.js` 起服务时自带任务总线：页面按钮 → `jobs/<id>.json` → 脚本类就地执行、智能体类排队等取件。

- `jobs/` 落在项目根，已 gitignore，属于本机运行态。
- 内置任务：`jkit-check` / `jkit-inspect` / `jkit-dry-run` / `jkit-deliver`（真投需 `confirm:true`）
  + 智能体类 `market-research` / `resume-rewrite` / `reply-draft` / `jd-explain`。
- 想加自己的动作，写 `config/local/jobs.json`：

```jsonc
{"kinds": {"rebuild-atlas": {"title": "重建图谱", "runner": "script",
                              "argv": ["python", "tools/build_atlas.py"], "timeout": 600}}}
```

`argv` 里可用占位符 `{conditions}` / `{platform}` / `{max}` / `{budget_min}`。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `node server.js` 打印「缺少 app.files.xxx」后退出 | 配置没复制或没填 | `cp config/demo/*.json config/local/` 后改占位符 |
| 页面点开是「兜底面板」（地址 + 重试/新标签/回首页） | `routes.json` 的 `url` 指向不存在的文件 | 核对 `url` 是项目根相对路径，文件确实在 |
| 首页 KPI 显示「—」 | 对应数据源没接 | 检查 `app.sources` 路径；接口会返回 `SOURCE_MISSING` |
| 投递台账页空、提示「暂无投递事件」 | `runs/*/ledger.jsonl` 没有数据 | 在 `runs/<run_id>/ledger.jsonl` 每行写一条 JSON（见 §0 数据模型） |
| 端口被占用 | 上一个实例没关 | 改 `app.port` 或关掉旧进程 |
| 改了页面没生效 | 浏览器缓存 / 没重启服务 | `static.cache_control` 默认 `no-store`；改配置后重启 `node server.js` |
| 改模板后主应用没变 | 忘了重新 build | `node app/build.js` |
| 点「试跑」没反应 | 任务被拒或浏览器没连上 | 看 `GET /api/jobs` 的 `jobs[].error`；真投前确认浏览器插件已连 |
| 投递条件页显示「还没有任何方向条件」 | `config/local/conditions/` 为空 | 参照 `config/conditions.example.json` 建一份，`profile_ref` 指向你的画像 |
| 改了 `profile.json` 但条件没变 | Python 进程缓存 | 重启 `node server.js`；条件详情按文件 mtime 缓存，画像变更需要重开服务 |

## 8. 自检

```bash
# 敏感串扫描（白名单文件零命中才允许发布）
python tools/verify_template.example.py sensitive
```

你自己的真实值（手机号、城市、公司名）写进 `config/local/` 和 `rules/local/`（gitignored），
**永远不要写进 `*.example.json` 或页面源码**——那些会被当成模板发布。
