# SOP · 完整求职工作流（从岗位判断到面试复盘）

> 落盘 2026-11-17。这份是**操作手册**：按阶段告诉你要做什么、点哪里、数据落在哪、注意什么。
> 当前系统已跑通的阶段标注 ✅；尚在开发（范围见 `系统优化-最终范围基线.md`）的标注 🔧，避免误以为已可用。
>  compounds：页面操作细节见 `交互说明.md`；调研口径见 `岗位调研SOP.md`；迭代开发流程见 `迭代SOP.md`。

---

## 阶段 0 · 准备（每次开干前）

1. **起服务**：双击项目根 `启动招聘服务.bat`（8787）与 `启动管道服务.bat`（Named Pipe）。页面：`http://127.0.0.1:8787/workbench`。
2. **真投/联网抓取前探活浏览器**：命令行跑 `bsk browsers`，能看到已登录 Edge 才行；报"没有已连接的浏览器"就是 daemon 没起 → 后台跑 `bsk daemon start --foreground`。**daemon 不随会话保活，每次新会话都要查**。
3. 确认 BOSS/智联在浏览器里**已登录**（真投和登录态调研都依赖它）。

---

## 阶段 1 · 岗位判断与分析 ✅

1. 进 ①「岗位判断与分析」→「我是谁」：填画像（学历/年限/技术栈/期望/岗位想法），保存 → 写 `config/local/profile.json`。
   - 🔧 材料上传（PDF/Word 简历）与"先判断用户岗位"流程在开发中；当前以画像表单为准。
2. 点「开始分析」：秒级确定性基线，读画像 × 岗位族市场快照 → 出方向推荐表（评分/档位/命中/样本/薪资）。
3. 点结果行：就地展开该族详情（能力全景、门槛、能力项三档、JD 原文摘录）。**样本 ≤1 条时面板会显式警告"参考度低"，不要当成结论**。
4. 想要真实判断：点「交给 WorkBuddy 深析」→ 任务面板复制指令 → 粘进 WorkBuddy 会话执行 → 结果回写后在「执行记录」看。
   - 🔧 联网调研（BOSS/智联登录态抓真实 JD + 来源 URL）在开发中。

**红线**：不编造岗位名；联网结果必须带真实来源 URL；样本薄就如实说"参考度低"。

---

## 阶段 2 · 投递条件 ✅

1. 进 ②「投递条件」：六份方向条件一屏看全，每份有 L0–L4：
   - L0 平台原生筛选（城市码/求职类型/学历/经验）——可改可存；
   - L1 搜索词；L2 硬否决；L3 方向词；L4 投放控制（单轮上限/预算/数量）。
2. 改完点保存 → `PUT /api/conditions` 白名单写回条件文件（写前自动留档到 `runs/backup/`）。
3. **生效口径**：条件每次运行实时读盘；「单轮投出上限」`f_max` 留空 = 用条件文件的值 / 不限（不会偷偷塞默认值覆盖你）。

---

## 阶段 3 · 试跑与真投 ✅

1. **试跑（可选）**：填"试跑条数"（默认 8）→ 点「试跑 N 条」。只判不投，出逐条判定表。试跑**不是**真投的前置步骤。
2. **真投**：点「真实投递」→ 8 秒内**再点一次**确认 → 建 `jkit-deliver` 任务（带 `confirm:true`）。
   - 真投会打开浏览器按当前条件投递，**跑的时候别动那个标签页**。
3. 数量闭环：设了 N 条就只把"真实投出"计入，投够 N 停；候选不够会显示"目标 N 条，成功 X 条，候选耗尽"（不会假装完成）。
4. 每条都进详情二次校验：卡片看着合格但详情不满足（薪资/地点/经验/今日不在线/JD 太短）→ 跳过并继续找下一条。

**安全底线**：真投二次确认不可绕过；同公司本轮只投一次；命中风控/配额立即停；冷却期零请求。

---

## 阶段 4 · 看结果回显 ✅

1. 任务面板（右上角「🧩 任务指令」）→「执行记录」：按时间显示每条任务的**指令 → 回执 → 结果 → AI 写入**，可按 kind 过滤、刷新、点开看四段全文。**刷新页面不丢**。
2. 投递台账（②段产物）：看每次投递的批次/公司/岗位/结论。
   - 「依据/判定」可展开：否决项 / 判定依据 / 评分 / HR 状态 / JD 摘录 → 看清"为何跳过、为何投"。
   - 「条件快照」显示本次实际生效条件 + 目标完成情况。

---

## 阶段 5 · 跟踪与回复 ✅

1. 进 ③「招聘跟踪」→「今日跟踪」：看面试/待回复优先卡片；点「抓取今日动态」建 `track-sync` 任务，WorkBuddy 只读抓 BOSS/智联消息后回写展示（**不改台账、不发消息**）。
2. 主表增删改查：这是唯一可写页面，编辑状态/备注 → 写 `data/ledger.json` + 重生成 CSV。
3. 清理：只做"手动 + 提醒"，命中规则的记录**打标不删**，确认后才删（绝不自动定时删）。
   - 🔧 待清理提醒横幅、宽松布局开关在开发中。

## 阶段 6 · 面试准备与复盘 🔧（开发中）

计划流程：跟踪记录里对进入面试的岗位点「生成面试材料」→ WorkBuddy 按 `interview_prep` SOP 产出准备清单 → 记录面试时间/轮次/方式/状态 → 面完 AI 辅助回写结果 → 做复盘分析。当前模板已备，页面入口与产出回显尚未接通。

## 附录 A · agent 任务怎么执行（手工触发契约）

所有智能体任务都不是点了就自动跑，而是：

```
点按钮建任务 → 任务面板复制指令 → 粘到 WorkBuddy 会话 → 会话按 SOP 执行
   → 会话调 POST /api/job/:id/result 回写 → 工作台时间线看到结果
```

WorkBuddy 常驻自动取件能力未证实，系统不假装接通；这条手工链路是可靠闭环。回写后任务从 pending 转 done，不会卡住。

## 附录 B · 三条硬边界

1. 真投必须二次确认（页面连点两次 / 管道 CONFIRM 码），不可绕过。
2. 不编造岗位名与经历数字；联网详情必须有真实来源 URL。
3. 原始分析不可覆盖——编辑走 overlay，原始哈希不变，可对照/重置。
