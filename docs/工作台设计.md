# 求职工作台 · 设计文档

> 版本：v2（2026-11-15）
> 适用对象：想把这套工作台换到自己的求职场景、或想二次开发的人。
> 本文是**通用版**设计文档：文中出现的族数、样本数、文件路径均为示意值，
> 实际由 `config/` + `rules/` 和目录扫描决定，不含任何个人数据。
>
> 本文描述的是**完整系统**；本仓库只包含「表现层 + 只读接口 + 配置骨架」。
> 文中提到的 `server.js`（生产服务与主应用）、采集器、清理脚本、简历生成器**不在本仓库**，
> 见 README 的「这个仓库有什么、没有什么」。

```
┌──────────────────────────────────────────────────────────────────────┐
│  ☰  求职工作台   ›  ① 岗位判断 / 岗位族匹配判断      ●   🧩 任务指令 ↻ ↗ │  ← 外壳顶栏：位置 + 动作
├───────────────┬──────────────────────────────────────────────────────┤
│ ⌕ 搜索        │  [岗位族匹配判断][方向分析报告][方向分析·原稿]    i   │  ← 视图条：本段的产物
│               ├──────────────────────────────────────────────────────┤
│ 🏠 首页       │                                                      │
│ ─────────     │                                                      │
│ 求职流程      │              这一段的主视图（iframe）                 │
│ ① 岗位判断 3  │                                                      │
│ ② 市场调研 5  │                                                      │
│ ③ 简历定制 6  │                                                      │
│ ④ 投递     2  │                                                      │
│ ⑤ 跟踪回复 1  │                                                      │
│               │                                                      │
│ ┌ 数据概况 ┐  │                                                      │
│ │族  样本  │  │                                                      │
│ │条目 在招 │  │                                                      │
│ └──────────┘  │                                                      │
├───────────────┴──────────────────────────────────────────────────────┤
```

三句话概括：

1. **外壳只做导航和展示，不做业务判断**——左侧六个入口是「系统有什么功能」，
   右侧视图条才是「这个人跑出了哪些文件」。
2. **页面不调用任何模型**。分析、话术、复盘由外部 AI 会话（本工作区是 WorkBuddy）
   执行，产物落本地目录，工作台只读列举。
3. **没有任何实例值写死在页面里**。导航、产物、数据源路径、阈值全部来自
   `config/` + `rules/`，换一个人只需改配置。

## 1. 定位与边界

### 1.1 它是什么

一个**本地运行**的求职流程工作台：把「判断方向 → 调研市场 → 定制简历 → 投递 → 跟踪回复」
五个阶段的产物串到一条链路上，用统一外壳承载，让人不用记路径、不用在十几个 HTML 之间跳。

### 1.2 它不是什么

| 不做 | 为什么 |
|---|---|
| 不在页面里调模型 / 存 API Key | 密钥面在前端等于泄露；分析质量也不该被页面绑死 |
| 不触发采集、投递、回复 | 投递是不可逆动作，必须在有确认的场景里发生 |
| 不复制数据 | 页面全部读原文件；只有 `unified_data.json` 一个可写主库，且只由主应用写 |
| 不做「智能推荐」 | 推荐需要模型，模型在外部会话里；页面只呈现已有事实 |

### 1.3 唯一可写的地方

- 主库 `unified_data.json`：只由「⑤ 跟踪与回复 → 招聘跟踪」主应用写（备份 + 原子写 + CSV 重生成）。
- 该页面在路由里被标 `"writable": true`，外壳会在面包屑旁显示黄色「可写」徽标。
- 其余所有页面一律只读；外壳本身零写请求。

## 2. 分层架构

```
┌────────────────────────────────────────────────────────────┐
│ 表现层  工作台.html（壳）                                   │
│         ├─ 侧栏：首页 + 五段入口（路由驱动）                 │
│         ├─ 视图条：段内产物切换（接口合成）                  │
│         ├─ 内容区：iframe 承载既有页面                      │
│         └─ 任务抽屉：WorkBuddy 任务指令（纯剪贴板）          │
├────────────────────────────────────────────────────────────┤
│ 页面层  工作台-首页 / 工作台-岗位判断 / 工作台-投递台账       │
│         工作台-文档 / 招聘跟踪总览 / survey 图谱 / resume/*  │
├────────────────────────────────────────────────────────────┤
│ 接口层  server.js（零依赖 Node，端口 8787）                  │
│         ├─ /api/routes          ← 合成：routes.json + 扫描   │
│         ├─ /api/job-families    ← 族匹配数据 + 版本映射       │
│         ├─ /api/ledger-index    ← runs/*/ledger.jsonl 只读聚合│
│         ├─ /api/doc             ← 白名单 Markdown 原文       │
│         ├─ /api/workbuddy/*     ← 任务模板元数据 / 结果清单   │
│         ├─ /api/config          ← 前端可见的配置子集         │
│         └─ /api/ai              410（已停用，保留 stub）      │
├────────────────────────────────────────────────────────────┤
│ 数据层  本地文件：JSON / JSONL / CSV / Markdown / HTML        │
│         没有数据库，没有缓存层，改文件即生效（下次请求）      │
└────────────────────────────────────────────────────────────┘
```

**为什么用「壳 + iframe」而不是把页面重写成 SPA**：

- 已有页面（图谱、简历索引、跟踪主应用）都是独立可用的成品，重写等于重做视觉和逻辑，
  且会破坏「双击就能打开」的能力。
- iframe 天然隔离样式与脚本：图谱页的 1 MB 单文件、简历页的 A4 浅色主题、主应用的
  表格密集布局，彼此不打架。
- 代价是跨页面共享状态要靠 `postMessage` / 同源钩子，所以只做了一层薄钩子
  （`window.wbOpen(itemId, viewId)`），不传业务数据。

## 3. 信息架构：入口 vs 产物

这是本设计里最容易被做错的一层。

### 3.1 两层分离

| 层 | 位置 | 内容 | 数量 | 变化频率 |
|---|---|---|---|---|
| **入口** | 左侧导航 | 首页 + 五段流程 | 固定 6 行 | 极少（加一段才变） |
| **产物** | 右侧视图条 | 主视图 + 该段所有报告 / 版本 / 快照 | 每段 1–N 个 | 每次跑完都变 |

反例（改造前的版本）：把「方向分析报告」「AI 产品经理简历」「11-14 16:57 快照」
直接平铺进侧栏。结果是 15 个平级条目、没有任何层级，而且这些是**一次性数据**，
换人、换期就全错。侧栏描述的是「系统有什么功能」，不是「我跑出了哪些文件」。

### 3.2 五段的业务含义

| 段 | key | 输入 | 输出 | 主视图 |
|---|---|---|---|---|
| ① 岗位判断 | `judge` | 简历与个人情况 | 排序后的方向建议 | 岗位族匹配判断表 |
| ② 市场调研 | `research` | 候选岗位方向 | 真实样本 JD、门槛分布 | 岗位族图谱 |
| ③ 简历定制 | `resume` | 族画像、技术栈顺序 | 对应版本的简历 | 族简历索引 |
| ④ 投递 | `deliver` | 筛选条件、简历版本 | 投递事件流水（append-only） | 投递台账 |
| ⑤ 跟踪与回复 | `track` | 扫描产物 | 跟进状态、AI 任务指令 | 招聘跟踪总览（唯一可写） |

段的「输入 / 输出 / 下一步」写在 `routes.json` 的 `groups[].flow` 里，用 `｜` 分隔，
形如 `输入：简历与个人情况｜输出：排序后方向建议｜下一步：挑 2-3 个族做市场调研`。
壳层把它解析成「流程说明」浮层（视图条右侧的 `i` 按钮），不常驻占高度。

### 3.3 产物怎么进视图条

两条来源，互不冲突：

```
routes.json 的 variants（手工声明，位置确定）
        ┐
        ├─→ buildRoutes() 合并去重 → /api/routes → 视图条
app.json 的 artifact_scans（通配扫描，自动发现）
        ┘
```

- **手工声明**适合一次性文本报告（方向分析、扫描报告），URL 稳定、顺序可控。
- **目录扫描**适合会不断新增的东西（简历版本 `简历_*.html`、图谱快照
  `survey/*/atlas.html`）。新增一个文件，刷新即出现，**不用改代码**。

扫描规则支持：`pattern`（同层 glob）、`label_from`（dirname / filename）、
`strip_prefix`、`label_date`（把 `20261114-1657` 压成 `11-14 16:57`）、`exclude`、
`sort`（name / mtime_desc / mtime_asc）、`limit`。

## 4. 数据流：引用，不拷贝

```
事实链   identity.json + 简历事实.md
          → 外部 AI 会话 → workbuddy_out/analysis|outreach|interview_prep|effect_review/*.md
          → 工作台只读列举（任务抽屉里的「已落盘结果」）

调研链   survey/**（只读）
          → 外部会话产条件草案 → workbuddy_out/condition_drafts/*.json（approved:false）
          → 人工审阅后另建条件与 run

投递链   runs/*/ledger.jsonl（append-only，不回改）
          → /api/ledger-index 内存只读聚合 → 投递台账页

跟进链   平台扫描产物 → unified_data.json ← 主应用（唯一可写）
          → 两份 CSV 重生成 → 跟踪总览 / 跟进列表
```

**关键约束**：

- `ledger.jsonl` 是追加型事实源。工作台只做「读 + 聚合成视图」，不写、不改、
  不回填历史。稳定 ID = `批次:行号:去重键`（`job_id` 优先，退回「公司|标题」）。
- 条件快照只存**路径字符串**，不解析内容。两套 schema 不强行统一。
- 主表 `unified_data.json` 只留「有沟通、有后续机会」的记录，海投流水不灌进去。

## 5. 接口契约

所有接口只读，`GET`，无鉴权（本地 127.0.0.1），外层统一包一层 `{ok, ...}`。
**壳层只依赖 `j.routes` 这样的外层字段**——早期实现漏过这层包装，页面直接拿到 `null`。

### 5.1 `GET /api/routes`

合成的导航树。**服务端合成，浏览器不做拼接**，这样「新增数据自动出现」只需要改配置。

```jsonc
{
  "ok": true,
  "routes": {
    "synthesized": true,
    "groups": [
      { "id": "home", "label": "首页", "order": 0, "kind": "link" },
      { "id": "judge", "index": "①", "label": "岗位判断", "order": 1,
        "flow": "输入：…｜输出：…｜下一步：…" }
    ],
    "items": [
      { "id": "home", "role": "link", "group": "home", "url": "工作台-首页.html" },
      { "id": "judge_matrix", "role": "primary", "group": "judge",
        "label": "岗位族匹配判断", "url": "工作台-岗位判断.html",
        "writable": false,
        "variants": [
          { "id": "direction_html", "label": "方向分析报告",
            "url": "reports/方向分析.html", "source": "config", "mtime": "" },
          { "id": "scan:简历_示例岗位.html", "label": "示例岗位",
            "url": "简历_示例岗位.html", "source": "scan",
            "mtime": "2026-01-01T00:00:00.000Z" }
        ] }
    ],
    "totals": { "groups": 6, "items": 6, "variants": 12, "scanned": 6 }
  }
}
```

合成规则：

1. `groups` 按 `order` 排序；`kind: "link"` 的组直接产出一个 `role: "link"` 的入口。
2. 每个普通组产出一个 `role: "primary"` 的入口：取该组内显式 `role: "primary"` 的项，
   没有就取第一个（兼容旧的平铺配置）。
3. `variants` = primary 的 `variants` + 同组其它项 + 扫描结果，按 `url` 去重，
   且不会把 primary 自己塞进去。
4. 扫描结果按 `artifact_scans` 顺序追加，标签用 `label_date` 等规则格式化。

### 5.2 其它接口

| 接口 | 返回 | 缺失时 |
|---|---|---|
| `/api/job-families` | 族匹配分、分档、在招/样本、族简历映射、图谱深链 | `code: "NO_SOURCE"` |
| `/api/ledger-index` | 台账聚合（`totals` 含 files/runs/lines/parsed/bad_lines/delivered/outcomes） | `ok:false` |
| `/api/doc?src=` | Markdown 原文 | 越界 400 / 非白名单 403 / 非 md 400 |
| `/api/workbuddy/tasks` | 任务模板元数据（id/title/trigger/output_path/inputs/output_schema） | 空数组 |
| `/api/workbuddy/results` | 产物目录与文件名（不读内容） | `totals.files: 0` |
| `/api/config` | 前端可见配置子集（adapter / output_root / tasks_ref / channels / 标题） | — |
| `/api/ai` | `410 Gone` + 说明 | — |

`/api/doc` 的三道闸门：路径必须落在 `sources.doc_roots` 之内 → 文件必须在
`sources.doc_allow` 白名单里 → 扩展名必须 `.md`。任何一条不满足就拒绝，
**不做「相对路径拼接后规范化」这种容易出错的宽松处理**。

## 6. 配置参考

三级优先级：`config/local/*.json`（工作区实例，gitignored）> 项目内默认实例 >
`config/*.example.json`（通用骨架）。

### 6.1 `config/local/app.json`

| 键 | 作用 | 默认 |
|---|---|---|
| `port` | 服务端口 | `8787` |
| `output_root` | 外部会话产物根目录 | `workbuddy_out` |
| `result_dirs` | 产物子目录 key → 路径 | `analysis` / `outreach` / `interview_prep` / `effect_review` / `condition_drafts` / `ledger_index` |
| `tasks_ref` | 任务模板目录 | `templates/workbuddy/tasks` |
| `workbench_title` | 顶栏与标签页标题 | `求职工作台` |
| `sources.job_families` | 族匹配分数据文件 | — |
| `sources.resume_versions` | 族名 → 简历文件映射 | — |
| `sources.atlas_deep_link` | 图谱族详情深链模板 | — |
| `sources.doc_roots` / `doc_allow` | Markdown 白名单目录 / 文件 | — |
| `artifact_scans[]` | 段内产物的自动发现规则 | 见下 |

`artifact_scans` 示例：

```jsonc
{
  "group": "resume",
  "pattern": "简历_*.html",
  "label_from": "filename",
  "strip_prefix": "简历_",
  "sort": "name",
  "badge": "版本",
  "note": "新增简历文件自动出现在「简历定制」的视图切换里，不用改配置"
}
```

### 6.2 `config/local/routes.json`

```jsonc
{
  "version": 2,
  "groups": [
    { "id": "home", "label": "首页", "order": 0, "kind": "link", "url": "工作台-首页.html" },
    { "id": "judge", "index": "①", "label": "岗位判断", "order": 1,
      "flow": "输入：简历与个人情况｜输出：排序后方向建议｜下一步：挑 2-3 个族做市场调研" }
  ],
  "items": [
    { "id": "judge_matrix", "label": "岗位族匹配判断", "group": "judge",
      "role": "primary", "url": "工作台-岗位判断.html", "order": 0,
      "variants": [
        { "id": "direction_html", "label": "方向分析报告", "url": "reports/方向分析.html" }
      ] },
    { "id": "main", "label": "招聘跟踪", "group": "track", "role": "primary",
      "url": "招聘跟踪总览.html", "writable": true, "badge": "可写" }
  ]
}
```

字段含义：

| 字段 | 用在 | 说明 |
|---|---|---|
| `role` | item | `link`（首页直达）/ `primary`（段主视图）/ 省略（当作变体） |
| `writable` | item | 该页会写本地数据；外壳显示「可写」徽标 |
| `badge` / `badge_kind` | item / variant | 小徽标：`new` 蓝 / `write` 黄 / 其它灰 |
| `mode` | item | `embed`（页内打开，默认）/ `newtab`（仅作快捷键，不推荐） |
| `index` | group | 序号（①②③…），侧栏与卡片都用它 |
| `flow` | group | `输入：…｜输出：…｜下一步：…`，解析成流程说明浮层 |

> `mode: "newtab"` 曾经造成「导航点不动」的 bug：预览面板里 `window.open` 被拦截。
> 现在主点击一律页内打开，`↗` 才是次要的新标签动作。

### 6.3 其它单一源

| 改动意图 | 只改这一处 |
|---|---|
| 渠道 / CSV 顺序 | `config/local/channels.json` |
| 概率词表、分值、分级文案 | `rules/local/prob.json` |
| 清理阈值、权重、状态集合 | `rules/local/cleanup.json` |
| 岗位分类规则 | `job_family_rules.json`（`cleanup.py` 与 `server.js` 共用） |
| 任务模板 | `templates/workbuddy/tasks/*.md` |

## 7. 交互规范

### 7.1 键盘

| 键 | 动作 |
|---|---|
| `/` | 聚焦搜索框 |
| `[` | 显示 / 隐藏侧栏 |
| `R` | 重新加载当前页 |
| `Esc` | 关流程浮层 → 关任务抽屉 → 清空搜索（逐层） |
| `←` `→` | 视图条内切换 tab（焦点在 tab 上时） |
| `Enter` / `Space` | 打开聚焦的导航项 |

### 7.2 记忆（localStorage）

| key | 内容 |
|---|---|
| `wb.workbench.last` | 上次打开的入口 |
| `wb.workbench.views` | 入口 → 上次看的视图（JSON 对象） |
| `wb.workbench.hidden` | 侧栏是否收起 |

全部 try/catch 包裹：无痕模式或配额满时不报错，退化为「每次重新选」。

### 7.3 深链

`/workbench?open=<入口id>&view=<视图id>` 直达，优先于记忆。
落地后会把 query 清掉（`history.replaceState`），避免刷新时反复覆盖用户后来的选择。

### 7.4 反馈与兜底

| 场景 | 行为 |
|---|---|
| 页面加载慢（> 8s） | 加载遮罩补一行「可以点右上角 ↗ 在新标签打开」 |
| 页面 404 / 空白 | 内容区显示兜底面板：实际地址 + 排查提示 + 「重试 / 新标签 / 回首页」 |
| 复制任务指令 | 底部 toast，不用原生 `alert` |
| 内页自己跳转 | 面包屑尾部补「› 内页标题」，让人知道现在走到哪一层 |
| 内页自带侧栏 | 内页检测 `window.self !== window.top` 后进入嵌入模式，收起自己的侧栏 |

### 7.5 任务抽屉

WorkBuddy 任务指令面板是**覆盖式抽屉**（`position:fixed`，宽 384，从右滑出），
不是挤压式侧栏——挤压会让 iframe 重新布局、表格列宽跳变。

- 打开时内容区加半透明遮罩，点遮罩 / `Esc` / 关闭按钮都能收起。
- 点侧栏导航会自动收起抽屉，避免盖住刚打开的页面。
- 抽屉里只有元数据和「复制指令」按钮，零网络请求。

## 8. 视觉规范

| token | 值 | 用途 |
|---|---|---|
| `--bg` | `#14161a` | 页面底色 |
| `--panel` | `#1c1f26` | 侧栏、顶栏、卡片 |
| `--panel2` | `#232731` | 输入框、次级块 |
| `--line` | `#2e333e` | 分隔线、边框 |
| `--ink` / `--mut` / `--dim` | `#e8ebf1` / `#8b93a3` / `#6f7889` | 三级文字 |
| `--accent` | `#7aa8ff` | 选中、链接、进度 |
| `--ok` / `--warn` | `#5fd39a` / `#f0be5f` | 在線、可写 |

约定：

- **只读 = 深色，可打印 = 浅色**。简历是 A4 浅色（打印用），嵌进深色壳里是刻意的对比，
  不强行统一。
- 侧栏 264px，导航项 36px 高，一屏放得下 6 行 + 数据概况卡。
- 表头固定，`table-layout:fixed` + 固定列宽；`≤940px` 先隐藏四维与薪资列，
  精确值仍在展开行里可看。
- 四维用**分色信号条**（绿 ≥75 / 黄 ≥50 / 红 <50）而不是文字，短板的颜色先跳出来。

## 9. 通用化：换到别的求职者 / 别的岗位

### 9.1 必须改的

| # | 改什么 | 位置 |
|---|---|---|
| 1 | 标题、端口、产物目录 | `config/local/app.json` |
| 2 | 五段与入口 | `config/local/routes.json`（`groups` + 每段一个 `role: primary`） |
| 3 | 数据源路径 | `app.json` 的 `sources` |
| 4 | 渠道 | `config/local/channels.json` |
| 5 | 岗位分类规则 | `job_family_rules.json` |
| 6 | 阈值 / 词表 | `rules/local/prob.json`、`rules/local/cleanup.json` |
| 7 | 事实源 | `config/local/identity.json`、`templates/resume_facts.example.md` |

### 9.2 不用改的

- `工作台.html`、`workbench_readonly.js`、`server.js`：都是配置驱动，零实例值。
- 新增数据只用丢文件：简历丢进根目录、新一期调研丢进 `survey/`，扫描规则自动收。

### 9.3 段数不是 5 也可以

五段是本工作区的业务形状，不是硬约束。`routes.json` 的 `groups` 想加几段加几段；
首页卡片用 flex 布局（`flex:1 1 calc(33.333% - 7px)`），3 个一行、最后一行自动撑满，
不依赖固定段数。

### 9.4 换成公开模板时要注意

工作区实例仓库含个人数据（账号、简历、台账、调研快照），**不能直接公开**。
建议双轨：实例仓库保持私有，另建一个空仓库只放 `tools/verify_template.example.py`
的导出白名单（同时跑 `sensitive` 扫描确认零命中）。

## 10. 安全阀与非目标

- 页面零模型调用：`/api/ai` 返回 410，页面里不存在 API Key、不存在外呼地址。
- 页面零写请求：写只发生在主应用；主应用之外全部只读。
- `/api/doc` 三道闸门（目录 / 白名单 / 扩展名）。
- 不批量读取产物内容：`/api/workbuddy/results` 只列文件名与大小。
- 不自动投递、不自动回复：工作台只「展示状态」和「给一段可复制的指令」。

## 11. 验收断点

```bash
python workbuddy_out/verify/verify_ui.py         # 64 项（导航/可达/扫描/首页/岗位族/文档/壳/交互）
python tools/verify_template.example.py sensitive # 导出白名单敏感串零命中
python tools/verify_template.example.py hash-check workbuddy_out/verify/hash-baseline.json
```

| 组 | 断言要点 |
|---|---|
| 导航结构 | 6 个入口 = 首页 + 五段；每段恰好一个 primary；侧栏主项不含文档页；旧版页面不在主项 |
| 可达性 | 所有入口与视图 HTTP 200（Markdown 走 `/api/doc` 校验正文） |
| 目录扫描 | 简历版本 ≥4、图谱快照 ≥2，标签格式 `MM-DD HH:MM`，primary 不重复出现在 variants |
| 首页 | 容器存在、走 `wbOpen`、说明 `artifact_scans` 来源 |
| 岗位族 | 族总数与配置一致、分档齐全、族→简历全映射、样本数与源文件一致 |
| 文档边界 | 白名单可读、返回 `text/markdown`、越界/非白名单/非 md 三种拒绝 |
| 壳结构 | 一行一个入口、视图条、流程浮层、剪贴板权限、`↗`、加载提示 |
| 交互 | 数据概况卡、页内位置、404 兜底、抽屉覆盖、toast、`?open=` 深链、可写标注、嵌入模式 |
