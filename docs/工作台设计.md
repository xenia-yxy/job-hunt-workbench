# 工作台设计

> 这份文档描述的是**系统本身**，不含任何个人数据。文中出现的族数、样本数、文件路径都是示意值，
> 实际由 `config/` + `rules/` 与目录扫描决定。

## 一、一句话

工作台是一个**外壳**：侧栏告诉你现在在哪一段，视图条告诉你可以看哪些产物，内容区只负责渲染当前那一个。
它不是又一个 dashboard —— 它把「看什么」和「改什么」分开，改只发生在唯一可写的那一页上。

## 二、三层结构

```
入口层   工作台.html（壳）              ← 唯一的导航真相
产物层   工作台-首页 / 定位 / 投递条件 / 投递台账 / 文档 / app.html
数据层   data/ledger.json ←→ CSV（派生）· runs/*/ledger.jsonl（事件流）
```

三层之间只有两条通道：

1. **入口 → 产物**：`config/local/routes.json` 的 `groups` + `items`。壳按 `items[].role = primary`
   渲染每段一行，`variants` 渲染成视图条上的标签。
2. **产物 → 数据**：所有写操作都打到同一组 `/api/data` 接口，由 `data_store.js` 统一落盘。

## 三、为什么入口和产物要分层

早期版本把「导航」和「内容」写在一起，结果是每加一个报告就要动一次侧栏，侧栏很快变成文件树。
现在：

- **侧栏只描述流程**：首页 → ①岗位判断 → ②投递 → ③跟踪。段数由你的求职链路决定。
- **产物挂在段下面**：同一个动作产出的东西（表格、报告、简历、台账）都在视图条里切换，不进侧栏。
- **自动发现**：新增产物不必改路由——`config` 的 `artifact_scans` 按通配扫描目录，命中即成为变体。

加一份报告的成本是「把文件放进去」，不是「改三个地方」。

## 四、数据模型：两套数据，职责不同

| | 跟踪台账 | 投递事件流 |
|---|---|---|
| 文件 | `files.data`（默认 `data/ledger.json`） | `runs/<run_id>/ledger.jsonl` |
| 写入方 | 人（页面增删改查） | 机器（投递引擎，只追加） |
| 可变 | 可改可删 | 不可改，只能追加 |
| 结构 | 按渠道分组的记录数组 | 每行一个动作（投出 / 跳过 / 停止） |
| 用途 | 跟人打交道、记状态和备注 | 复盘判定对不对 |

第三份是**画像**（`config/local/profile.json`）：不是台账，也不是流水，是「我是谁 + 我要什么」。
它只存对判断有用的属性——年龄、学历、专业、届别、城市、工作年限、技能栈、期望薪资、底线条件。
**不存姓名**：判断一个岗位要不要投，名字一点用没有，留着只增加泄露面。

画像有两个写入方（页面手填、简历解析回写），所以只留一个写入口 `profile_store.js`：
深合并补丁、逐字段记来源（`manual` / `resume` / `agent`）、写前留档到 `runs/backup/`。

**三者不合并**：事件流是历史事实（投过就是投过），台账是当前状态（现在要跟谁聊），
画像是判断依据（够不够格、要不要去）。
它们之间只有一条单向、幂等的通道：`POST /api/ledger/import` 把事件流里 `outcome=delivered`
的行按 `job_id` 去重写进台账，并在记录上留 `source_refs` 指回原始 run。

## 五、写盘契约（这一层的四条硬规则）

1. **JSON 是唯一真相。** 两份 CSV 是每次写盘后重算的派生品。CSV 写失败只降级为告警
   （接口返回 `csv_warning`），绝不把「数据已落盘」变成「接口失败」——否则页面会误判为离线，
   之后所有改动只写浏览器本地，看起来成功、磁盘上空空。
2. **记录级写入。** 增 / 改 / 删各自打到 `POST|PATCH|DELETE /api/data/:channel/:id`，
   只影响这一条。整份覆盖只在批量导入时使用，且必须带 `baseVersion`。
3. **版本号。** 每次写盘产生新的 `version`（内容短 hash）。带 `baseVersion` 的写入若已过期，
   返回 409 + 最新数据，由页面决定重载，服务端不替用户做合并。
4. **串行化。** 同一进程内所有写入排进一条队列，读改写不会交错；落盘用临时文件 + rename，
   不会留下写了一半的文件。

对应的回归测试：`tests/test_client_write.js` 六项，逐条钉住「失败不关服务端模式」「409 重载」
「CSV 失败只告警」。

## 六、接口契约

| 方法 | 路径 | 语义 | 失败码 |
|---|---|---|---|
| GET | `/api/data` | 整份读 | — |
| PUT | `/api/data` | 整份写（批量导入 / 恢复），可带 `baseVersion` | 409 `VERSION_CONFLICT` |
| POST | `/api/data/:channel` | 新增一条 | 400 `BAD_RECORD` |
| PATCH | `/api/data/:channel/:id` | 改一条（深合并，数组整体替换） | 404 `NOT_FOUND` |
| DELETE | `/api/data/:channel/:id` | 删一条 | 404 `NOT_FOUND` |
| POST | `/api/ledger/import` | 事件流回流，幂等；`dry_run` 只预演 | — |
| POST | `/api/restore` | 用上一份备份覆盖 | 404 无备份 |
| POST | `/api/profile` | 画像深合并（可只带一个字段），首次调用建档 | 400 `BAD_BODY` |
| POST | `/api/resume/upload` | 上传简历（base64，≤8MB），存文件 + 抽文本 + 提字段 | 413 `TOO_LARGE` |
| GET | `/api/resume/list` | 已上传简历列表（含解析质量与字段） | — |
| GET | `/api/resume/text?id=` | 某份简历的纯文本 | 404 |
| DELETE | `/api/resume/:id` | 删这份文件与文本（不动已写入的画像值） | 404 |
| POST | `/api/resume/apply` | 把确认过的字段写进画像，记来源 `resume` | 400 `NO_FIELDS` |

只读聚合（页面用来渲染，不提供写）：`/api/routes`、`/api/config`、`/api/job-families`、
`/api/ledger-index`、`/api/conditions`、`/api/profile`。

约定：所有写接口成功都返回 `version`；页面拿它做「我看到的 = 磁盘上的」的唯一凭据。

### 简历解析的边界

- 支持 `.docx`（zip + `word/document.xml`）、`.pdf`（解 flate 流抓文本层）、`.txt/.md/.html`。
  **不引第三方库**：clone 下来就能跑，不为一个上传功能引入需要编译的依赖。
- 老 `.doc`、扫描件 PDF、子集字体 PDF 抽不出可信文本时，返回 `quality: low|empty` 并给提示，
  **不猜**——硬猜只会写出乱码。页面提供「粘正文」入口走同一条提取链路。
- 提取结果一律先展示（值 + 原文依据），人勾选确认后才写入；默认「只填空位」，
  要覆盖已有值需显式勾选。技术栈按并集合并，不会把已有技能冲掉。

## 七、配置边界

代码里没有任何默认文件名、端口、渠道名。缺项直接退出并打印缺什么，不静默兜底——
静默兜底会写错文件，比报错难查得多。

| 配置 | 提供什么 | 缺了会怎样 |
|---|---|---|
| `app.json` | 端口、数据文件名、页面路由、构建目录、只读数据源 | 服务启动即退出 |
| `channels.json` | 渠道清单、CSV 顺序与表头、渠道概率加分 | 服务启动即退出 |
| `routes.json` | 侧栏分段与每段主视图 | 侧栏空，页面仍可直连 |
| `identity.json` | 招呼语 / 任务指令里的自我描述（**不含画像**） | 任务指令缺主语 |
| `profile.json` | 画像：属性 + 需求 + 筛选口径 | 首次保存时自动建档 |
| `workbuddy.json` | 任务接口位、产物目录 | 任务抽屉不可用 |
| `rules/*` | 概率口径、岗位族分类、清理口径 | 对应功能报错或降级 |

`config/local/` 覆盖 `config/*.example.json`；前者 gitignored。

## 八、通用化步骤（换一个人用，要动哪些）

1. `python tools/setup.py` —— 示例配置落 local、建空台账、跑一次构建。
2. 改 `config/local/identity.json` —— 名字、届别、城市、招呼语、技术栈。
3. 改 `config/local/channels.json` —— 自己的渠道清单（加一个渠道只改这一处）。
4. 改 `config/local/routes.json` —— 自己的链路有几段、每段主视图是哪个文件。
5. 改 `rules/local/*.json` —— 概率与岗位族口径。
6. 产物放进目录即可：命中 `artifact_scans` 就出现在视图条，不用改代码。

## 九、验收断点

| 断点 | 判据 |
|---|---|
| 冷启动 | 全新 clone → `setup` → `start`，工作台三段全部 200，无需手工改文件 |
| 写盘 | 增一条 → 重启服务 → 记录还在；改状态 → 刷新 → 状态还在 |
| 失败可见 | 把 CSV 目录设成只读，改一条记录：数据落盘、界面出现 CSV 告警、连接状态仍是「已落盘」 |
| 冲突 | 两个标签页同时改不同记录，两边都不丢 |
| 回流 | 跑一轮投递 → 点「写入跟踪台账」→ 台账出现对应记录；再点一次不重复 |
| 脱敏 | `python tools/verify_template.example.py sensitive` 零命中 |
