# 工作台使用说明

> 更新 2026-11-17。面向使用者：这套工作台怎么用、四段流程怎么走、新功能在哪、遇到问题看哪里。
> 技术设计见 `docs/工作台设计.md`；完整链路见 `docs/设计流程说明.md`。

## 1. 启动

需要两个本地服务（本项目根目录各有一个 `.bat`，双击即可）：

| 服务       | 端口         | 作用                            | 启动脚本         |
| -------- | ---------- | ----------------------------- | ------------ |
| 工作台服务    | 8787       | 页面 + 只读接口 + 任务总线              | `启动服务.bat` |
| 管道服务（可选） | Named Pipe | 本机命令行下指令（帮助 / 状态 / 分析 / 投递确认） | `启动管道服务.bat` |

打开浏览器访问 `http://127.0.0.1:8787/`，从「工作台.html」进入。工作台是**壳 + 内嵌页**：  
左侧导航切页，右上角「🧩 任务指令」抽屉放 WorkBuddy 任务模板与只读结果列举。

## 2. 四段流程

```
⓪ 我的档案        →  ① 岗位判断与分析  →  ② 投递        →  ③ 跟踪与回复
   简历 + 情况 + 需求      方向排序 + 市场友好度      条件 + 真投/试跑      状态 + 沟通 + 复盘
```

- **⓪ 我的档案**：上传简历自动读属性 → 核对个人情况（年龄/学历/专业/届别/城市/年限/技能）→
  填求职需求（方向/薪资/底线/出差驻场/到岗）→ 「分析我的需求」检查自洽性。
- **① 岗位判断与分析**：只读档案画像 → 写一句岗位想法 → 开始分析（秒级基线）→ 点结果看该族详情 → 交给 WorkBuddy 深析。
- **② 投递**：六份方向条件，每份五层（L0–L4），可改本方向差异项，改完可先试跑再真投；
  投递台账看每条投出 / 跳过的原因。
- **③ 跟踪与回复**：有沟通、有后续机会的记录；按规则清理只留重点。

所有页面只读聚合 + 白名单写入，工作台本身**不调模型、不采集、不投递、不回复**；  
这些动作要么由本地脚本任务执行，要么由 WorkBuddy 会话执行。


### 2.1 首屏与按钮位置（2026-11-17 调整）

- **打开就是首页**，不再恢复上次停在哪一页；要直达某页用 `?open=<入口id>`（可存书签）。
- **返回按钮在顶栏最左**（☰ 右边），只在有历史时出现，`Alt + ←` 同效。面包屑「首页 › 段 › 视图」的前两级也能点。
  内页里点链接会在同一个壳内换页并压栈，不会再整页跳走导致回不去。
- **首页是数据看板**：首屏常驻 6 个 KPI 方块（档案/条件/事件/已投/跟踪/沟通），
  下面是三个图表（流程漏斗 / 投递结果占比 / 跟踪状态）和跟踪明细表。
  四步链路与数据口径收在下面，点开才占屏。取不到的数据显示「—」，不补零。
- **卡片折叠统一在标题栏右侧**：`展开 / 收起`。展开的卡片整行铺开，收起的并排成摘要条。
  档案页不再用折叠——四个功能拆成四个视图，用顶栏视图条切换。
- **主按钮在卡片底部左侧**，状态文字靠右；标题栏右侧只放折叠和说明，不放主操作。
- **画像只有一个写入口**：我的档案。岗位判断页改成只读摘要 + 分析参数（岗位想法不落盘），
  避免两处表单互相覆盖；任何 `/api/` 写操作后，壳层与首页会读到新数据。

## 3. 本轮新功能怎么用

### 3.0 传简历 / 填档案（「我的档案」页）

0. 档案页现在是**四个独立模块**：顶栏视图条依次是「我的档案（简历）/ 我的情况 / 求职需求 / 需求分析」。
   一屏只做一件事，不再上下滚动找折叠。独立打开页面时，页头也会出现同样的四个切换按钮。
1. 在「简历」模块把简历拖进上传框（`.docx` / `.pdf` / `.txt` / `.md` / `.html`，≤8MB），或点选文件。
2. 解析完会给一张表：**字段 / 提取值 / 原文依据**。看不出来自哪里的值，先核对依据再勾选。
3. 默认「只填空位」——已有值不会被冲掉；要覆盖就勾「覆盖已有值」。技术栈按并集合并。
4. 点「写入档案」，四个角标会变：`手填` / `简历` / `分析`，一眼看出这个值是谁写的。

**只读属性，不读隐私**：姓名、电话、邮箱不提取、不入库。老 `.doc`、扫描件 PDF 抽不出文本时
不会硬猜，把正文粘到输入框，走同一条提取链路。

**需求分析**在本地算，秒级出结论：字段完备度、届别与年限是否矛盾、期望与底线是否打架、
方向有没有技能支撑、底线是否写成可执行条件；有岗位族市场数据时再补一条「你的底线在该方向能不能落地」。

### 3.1 改平台原生筛选（L0）

位置：投递条件页 → 选中一个方向 → L0「平台原生筛选」卡。

1. 城市码输入框改平台城市代码（纯数字）。
2. 各筛选项框改值；多个选项用 `/` 分隔（如 `应届生 / 1年以内`）。
3. 想删掉某项 → 把框清空。
4. 点「保存筛选」→ 自动留档 → 刷新生效。

要点：

- 只改**当前方向**，不影响其他方向；键名（求职类型 / 学历要求等）由平台固定，不在这里改。
- 默认值来自共享画像；单方向保存后以这里为准。
- 保存前自动备份到 `runs/backup/`，可随时还原。
- 学历 / 年限 / 技术栈这些**画像共性字段**仍在「岗位判断与分析 → 我是谁」里改，六方向共用。

### 3.2 看分析结果的族详情

位置：岗位判断与分析 → 分析结果表 / 市场全景表。

- 点任意一行 → 主区域切到该族详情（breadcrumb 显示来源，顶部有「← 返回结果」）。
- 详情含：能力全景 KPI、匹配分拆解、门槛项、能力项三档（绿框=你已有）、原文能力表述、  
  人工解读对照、门槛分布、薪资与发展、对你的匹配、JD 原文提取与样本统计。
- JD 原文 ≤1 条时页面会明确提示"参考度低，不能当作该族全貌"。
- 不再跳独立图谱页；`atlas.html` 仅作历史快照归档，不挂在导航。

### 3.3 让 WorkBuddy 真正分析你的岗位想法

位置：岗位判断与分析 → 我是谁 → 两个分析按钮。

| 按钮              | 做什么                                                | 何时用                     |
| --------------- | -------------------------------------------------- | ----------------------- |
| 开始分析            | 本地秒级打分（市场 35% + 技能 25% + 薪资 15% + 想法关键词 25%），给排序基线 | 想快速看哪个方向排前面             |
| 交给 WorkBuddy 深析 | 建 agent 任务，按 SOP 由会话读数据、**真正解读你的岗位想法**，结果回写        | 想搞清楚"为什么"、想法里的诉求与数据冲突在哪 |

操作：

1. （可选）在「岗位想法」框里写清楚你的诉求，如"想投交付，偏稳定，能接受出差驻场"。
2. 点「交给 WorkBuddy 深析」→ 页面显示"排队中 · 等 WorkBuddy 取件"。
3. 到 WorkBuddy 会话点「复制取件指令」把指令粘进去，或直接说"执行方向深度分析任务 job <id>"。
4. 会话按 SOP 读只读接口、出报告、回写结果；本页自动轮询显示结论与"想法解读"。

深析的硬约束（写死在任务模板里）：只读、不投递、不编造、JD 少要声明参考度低、  
只用于本人私下判断。它**不重算分数**——基线分照抄并注明来源，价值在解读与判断。

## 5. 常见问题

- **服务连不上**：确认 8787 服务在跑（双击 `启动招聘服务.bat`），页面健康检查点变绿。
- **分析按钮灰了**：当前工作区没有 `jkit/` 引擎（模板轨场景），接入引擎后自动可用。
- **深析一直排队**：agent 任务需要到 WorkBuddy 会话取件执行并回写，页面本身不调模型。
- **保存筛选失败**：城市码必须是 3–12 位数字；检查改的是不是存在的方向文件。
- **想还原筛选**：从 `runs/backup/` 找对应时间戳的备份 copy 回 `config/local/conditions/`。

## 5A. 今日跟踪（投递完成后看沟通 / 面试）

在工作台「跟踪与回复」段（跟踪台账页）顶部有一块 **📅 今日跟踪**：

- **打开就看**：直接从台账算出——面试 / 等我回复的排最前，其余近期沟通按录取概率列几条。  
  每张卡片给公司、岗位、渠道、最后消息、时间、和建议动作。来源标"台账快照"。
- **取平台最新**：点 **🔄 抓取今日动态** → 建一条只读抓取任务 → 到 WorkBuddy 会话里执行  
  （按 `templates/workbuddy/tasks/track_sync.example.md` 的 SOP 抓 BOSS / 智联消息）→ 回写后页面自动换成  
  "WorkBuddy 现场抓取"的最新动态；刷新页面也不会丢（自动载入最近一次结果）。
- **点 ?** 看口径说明。

### 口径与安全

- 本面板**只读**：不改台账、不发任何消息、不投递、不收藏；只给"建议更新哪些记录"，由你确认后自行处理。
- 台账快照来自本地数据，平台实时数据来自现场抓取；登录失效的渠道会在面板底部说明"未抓"，不猜测。
- 抓取是 agent 任务，需要到 WorkBuddy 会话取件执行，页面本身不调模型、不自动抓（避免无人值守碰平台）。

### 相关 FAQ

- **抓取一直排队**：agent 任务要你到会话里执行并回写；光点按钮不会自动抓。
- **面板显示的是旧快照**：点「抓取今日动态」并在会话执行回写后，会自动切到现场抓取数据。
- **某个渠道没数据**：可能登录失效，面板底部会写"未抓"；在浏览器登录对应平台再抓一次。

## 6. Git 与公开模板轨

- 实例轨（本仓库，Private）含真实数据，永不公开。
- 模板轨 `job-hunt-workbench`（Public）只有脱敏骨架 + demo；用 `python tools/sync_template.py --check` 校验后再同步。
- 工作流：本地 commit → 用户看清单确认 → 才 push。未经确认不做任何远端操作。
