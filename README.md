# 求职工作台

一个**跑在自己电脑上**的求职操作系统：我的档案 → 岗位判断 → 投递 → 跟踪，数据全部落在本地文件里，不上云、不登录、不写你的账号。

面向的场景很具体：

- 你有一堆投递渠道（校招网申、BOSS、智联…），信息散在收藏夹和备忘录里；
- 你想知道「这个岗位值不值得投」，但不想每条都重新想一遍；
- 你想记住「谁在等我回复」「哪条已经黄了」，而不是靠翻聊天记录。

它把这三件事变成：一份可筛选的判断依据、一条可复现的投递流水、一份可增删改查的跟踪台账。

---

## 三步跑起来

需要 Node.js ≥ 18 和 Python ≥ 3.9（只用标准库，不需要 pip 装任何东西）。

```bash
git clone <本仓库地址> job-hunt-workbench
cd job-hunt-workbench
python tools/setup.py        # 生成 config/local、建空台账、生成本地主应用页面
node server.js               # 或 npm start
```

打开 <http://localhost:8787/workbench>，从左到右就是四段的顺序。

### 第一件事：传一份简历

打开「我的档案」把简历拖进去（.docx / .pdf / .txt / .md / .html，8MB 以内）。
它只读**属性**——年龄、学历、专业、届别、城市、技能、期望薪资——抽出来先给你看原文依据，
你勾选确认后才写进档案。**姓名、电话、邮箱一律不提取、不入库**：判断一个岗位要不要投，
用不上这些。解析不了的老 `.doc` / 扫描件，把正文粘进去一样能提取。

想先看效果、不想先建自己的数据：

```bash
python tools/setup.py --demo --force   # 用仓库自带的演示配置与演示流水
```

### 第一次用，先改这一处

`config/local/identity.json` 里是占位身份（名字、届别、学校、城市、招呼语、技术栈）。
工作台生成的「任务指令」和简历方向都会引用它，改成你自己的再往下走。

## 它由什么组成

```
工作台.html              外壳：侧栏导航 + 视图条 + 任务抽屉（唯一的入口）
工作台-首页.html         数据看板：6 个 KPI 方块 + 三个图表 + 跟踪明细表；四步链路收在下面
工作台-档案.html         ⓪ 我的档案：一页一模块（简历/我的情况/求职需求/需求分析），顶部视图条切换
工作台-定位.html         ① 岗位判断与分析：只读消费档案 → 方向排序 → 选中方向出简历
工作台-投递条件.html     ② 投递条件：L0 筛选 / L1 搜索词 / L2 硬否决 / L3 方向词 / L4 投放控制
工作台-投递台账.html     ② 投递台账：append-only 事件流，每条投出 / 跳过都有原因
app.html                 ③ 跟踪台账（由 app/ 模板生成，唯一可写页面）

server.js                本地服务：静态托管 + 数据读写 + 任务总线
data_store.js            数据层：版本化 + 记录级 CRUD + 串行写（唯一写入口）
profile_store.js         画像写入口：深合并 + 字段来源标记 + 写前留档
resume_api.js            简历：上传、文本抽取（docx/pdf/txt）、字段提取、回写画像
assets/ui.css            统一视觉层：色板、字号层级、卡片/表单/按钮（各页引入即可）
ledger_import.js         投递流水 → 跟踪台账 的单向回流
workbench_readonly.js    工作台的只读聚合接口
job_bus.js               任务总线：页面按钮 → 本机脚本 / 等外部 AI 回写
prob.js                  录取概率引擎（页面与服务端同一份代码 + 同一份规则）
jkit/                    自动投递引擎（在你自己的浏览器里点按钮，不调隐藏接口）
cleanup.py               按固定口径清理台账（只留「有沟通 + 有后续」的记录）
```

配置全部外置，代码里没有一个默认文件名：

- `config/*.example.json` → 结构示例，开箱可跑的中性默认值
- `config/local/*.json` → 你的实例值（gitignored，优先于 example）
- `rules/*.example.json` → 概率与岗位族规则；`rules/local/` 放你的版本

## 数据怎么流

```
                 ┌──────────────────────────────┐
   页面增删改查 → │  data/ledger.json  唯一真相   │ ← 每次写入前自动备份
                 └──────────────┬───────────────┘
                                │ 派生（失败只告警，不影响落盘）
                                ├──→ data/ledger.csv
                                └──→ data/campus.csv
                 ┌──────────────────────────────┐
   自动投递   →  │ runs/<run_id>/ledger.jsonl   │ append-only 流水
                 └──────────────┬───────────────┘
                                │ POST /api/ledger/import（幂等，按 job_id 去重）
                                └──→ data/ledger.json（status=等对方，带 source_refs）
```

两套数据职责不同，不能混：

| | 跟踪台账 `data/ledger.json` | 投递流水 `runs/*/ledger.jsonl` |
|---|---|---|
| 谁写 | 页面（人） | 投递引擎（机器） |
| 能不能改 | 能，增删改查 | 不能，只追加 |
| 用来干什么 | 跟人打交道 | 复盘判定对不对 |

以前两者互不相通——投完 50 条，台账里一条都没有，要手工再录一遍。现在「投递台账」页有**写入跟踪台账**按钮，一步回流。

## 写盘这件事（踩过的坑都在这）

这一版把「改了但没存上」的根因逐条摁掉了：

1. **CSV 被 Excel 占用，接口返回 500，页面以为写盘失败。**
   实际 JSON 早就写好了。旧逻辑一旦失败就把页面永久切到「离线模式」，之后所有增删改查只写浏览器 localStorage——看起来成功，磁盘上一条没有。
   现在：JSON 是唯一真相，CSV 只是派生品，写失败返回 `csv_warning` 并在界面提示，**数据照常落盘**。

2. **整份覆盖导致丢数据。**
   旧逻辑每次改动都把整个数据集 PUT 回去。两个标签页、或者页面开着时后台刚投完一批，后写的会把先写的抹掉。
   现在：增 / 改 / 删走**记录级接口**，只动这一条；批量导入才整份写，且带 `baseVersion`，服务端发现版本过期返回 409，页面重新载入而不是硬盖。

3. **写完不等回执，关页就丢。**
   旧逻辑 fire-and-forget + 200ms 防抖，改完立刻关标签页就没了。
   现在：所有写入串行排队，成功以服务端回执为准，失败保留「重试」入口，连接状态里直接显示当前数据版本号。

对应的回归测试：`node tests/test_client_write.js`（6 项，逐条钉住上面三点）。

## 数据接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/data` | 整份读，返回 `data / count / version` |
| PUT | `/api/data` | 整份写（批量导入用），带 `baseVersion` 时校验冲突 |
| POST | `/api/data/:channel` | 新增一条 |
| PATCH | `/api/data/:channel/:id` | 改一条（深合并，数组整体替换） |
| DELETE | `/api/data/:channel/:id` | 删一条 |
| GET | `/api/data/:channel/:id` | 读一条 |
| POST | `/api/ledger/import` | 投递流水回流台账；`{"dry_run":true}` 只看会导几条 |
| POST | `/api/restore` | 用上一份备份覆盖 |
| GET | `/api/routes`、`/api/config`、`/api/job-families`、`/api/ledger-index`、`/api/conditions`、`/api/profile` | 工作台只读聚合 |

`version` 是数据内容的短 hash，每次写盘都会变。任何写操作成功后都会返回新版本，页面据此判断「我看到的」和「磁盘上的」是否同一份。

## 常见问题

**页面显示「○ 离线模式」**
服务没起来，或端口不是 8787。`node server.js` 后刷新；连接状态那行可以点，会重新探测。

**页面显示「○ 写盘失败 · 点此重试」**
数据目录不可写（权限 / 磁盘满 / 路径被占用）。修好后点一下那行文字就会重试，之前的改动不会丢。

**CSV 打不开或提示被占用**
不影响使用。关掉 Excel 后随便改一条记录，CSV 会自动重算。

**想清空重来**
删掉 `data/` 目录，再跑一次 `python tools/setup.py`。代码、页面、文档都不受影响。

**换了端口/文件名**
复制 `config/app.example.json` → `config/local/app.json` 改完重启。代码里没有默认文件名，缺项会直接报错而不是猜。

## 边界

- 不替你投递：`jkit` 是在**你自己已登录的浏览器**里点按钮，不调隐藏接口、不导出 cookie。
- 不替你判断：页面只做聚合与筛选，岗位值不值得投仍然是你拍板。
- 不上传任何数据：没有账号体系，没有云端，`data/` 里的东西只在你机器上。
- 页面内不调用大模型：需要分析时生成任务指令，你在自己的 AI 会话里执行，结果落回 `workbuddy_out/`。
