# 求职工作台 · Job Hunt Workbench

> 把「判断方向 → 调研市场 → 定制简历 → 投递 → 跟踪回复」五段流程的产物，串到一个本地页面里。
> 零依赖 Node、纯只读、页面不调用任何模型。换一个人用，只改配置，不改代码。
>
> 📄 **产品设计文档（PRD）**：[`docs/工作台设计.md`](docs/工作台设计.md) —— 12 章，含分层架构、
> 入口与产物的信息架构、`/api/*` 契约、配置参考、交互与视觉规范、通用化步骤、验收断点。

## 它解决什么

求职过程会产出大量文件：匹配判断表、调研图谱、十几份定制简历、投递台账、沟通记录、面试笔记。
它们各自都能打开，但**路径要记、状态要拼、下次从哪继续全靠回忆**。

这个工作台只做一件事：把这些**已经存在的页面**用一个外壳串起来，让你打开一个地址就看到全流程，
侧栏告诉你「系统有五段」，内容区顶部告诉你「这一段你手上有哪些文件」。

它**不做**采集、投递、回复、模型调用——这些都发生在工作台之外（你自己的 AI 会话或脚本里），
产物落到目录里，工作台自动发现。

## 三条设计原则

| 原则 | 落地 |
|---|---|
| **入口与产物分离** | 侧栏固定 6 行（首页 + 五段），描述「系统有什么功能」；右侧视图条才是「你跑出了哪些文件」，数量随数据变。产物是运行结果，不是导航结构 |
| **新增数据不改代码** | `app.json` 里写一条通配扫描规则（`简历_*.html`、`survey/*/atlas.html`），丢文件进去、刷新就出现。服务端合成 `/api/routes`，浏览器不做拼接 |
| **页面零写、零模型** | 所有接口 `GET` 只读；唯一的写操作在有明确确认的主应用里。分析、话术、复盘走「复制任务指令」到外部 AI 会话，结果落 `workbuddy_out/`，页面只列举文件名 |

## 快速开始

需要 Node 16+，无第三方依赖。

```bash
git clone <this-repo> && cd job-hunt-workbench

# 1. 复制配置骨架（4 份必需：app / routes / channels / identity）
cd config && for f in *.example.json; do cp "$f" "local/${f%.example.json}.json"; done && cd ..

# 2. 改 config/local/app.json 与 routes.json 里的 <占位符>
#    最少只需：app.port、routes.groups、每段一个 role=primary 的 item.url

# 3. 起服务
node serve.example.js          # → http://127.0.0.1:8787/workbench
node serve.example.js --port 9000
```

`<占位符>` 没替换前，壳与导航可以正常打开，点进去会看到**兜底面板**（实际地址 + 重试 / 新标签 / 回首页）——
这是刻意设计的降级，不是报错。先验证壳能跑，再逐段接上你自己的页面。

## 工作台怎么用

| 动作 | 方式 |
|---|---|
| 搜索 | `/` 聚焦搜索框，同时匹配段名与视图名 |
| 收起侧栏 | `[` |
| 重新加载当前页 | `R` |
| 逐层关闭 | `Esc`（流程浮层 → 任务抽屉 → 清空搜索） |
| 切换段内视图 | `←` `→`（焦点在视图条上） |
| 深链 | `/workbench?open=<入口id>&view=<视图id>`，可直接做书签 |
| 任务指令 | 右上 `🧩`，覆盖式抽屉里复制一段指令到 AI 会话，结果落盘后自动出现在「已落盘结果」 |
| 哪一页会改我的数据 | 面包屑旁的黄色「可写」徽标（`routes.json` 里 `"writable": true`） |

## 配置三件套

| 文件 | 决定什么 |
|---|---|
| `config/local/routes.json` | **导航形状**：`groups` 定义五段与顺序，`items` 里每段一个 `role: "primary"` 是侧栏入口，其余降级为视图条上的变体 |
| `config/local/app.json` | **数据从哪来**：`sources`（族匹配数据、简历版本映射、Markdown 白名单）+ `artifact_scans`（产物自动发现规则） |
| `config/local/channels.json` | 求职渠道与 CSV 列顺序 |

优先级：`config/local/*.json`（你的值）> `config/*.example.json`（通用骨架）。
缺 `app` / `routes` / `channels` / `identity` 任意一份，服务直接退出非 0——**不静默兜底**。

### 产物自动发现

```jsonc
{
  "group": "resume",            // 挂到 routes.json 的哪个段
  "pattern": "简历_*.html",      // 同层通配；* 只匹配一层，禁止 .. 与绝对路径
  "label_from": "basename",      // basename 去扩展名 / dirname 取父目录名
  "strip_prefix": "简历_",
  "sort": "name",                // name / mtime_desc / mtime_asc
  "exclude": ["简历_母版.html"],
  "badge": "版本",
  "note": "新增简历文件自动出现在视图切换里，不用改配置"
}
```

多跑一期调研、多定一版简历，文件丢进去刷新即出现。

## 换成你自己的流程

1. `config/local/routes.json` 改 `groups`——**段数不是 5 也可以**，首页卡片用 flex 布局，不依赖固定段数。
2. `app.json` 的 `sources` 指向你的数据文件；`artifact_scans` 指向你的产物命名习惯。
3. `templates/resume_facts.example.md` 换成你自己的事实源（这是唯一需要写自然语言的地方）。
4. `rules/job_family.example.json` 改成你的岗位分类关键词。

不用改：`工作台.html`、`workbench_readonly.js`、三个页面——它们不含任何实例值。

## 这个仓库有什么、没有什么

**有**：工作台外壳与四个页面、只读接口的完整实现、最小可跑服务、配置与规则骨架、任务指令模板、自检工具、设计文档。

**没有**（暂未开源）：

| 缺什么 | 为什么 |
|---|---|
| `server.js`（生产服务 + 主应用） | 里面还有工作区实例值（输出文件名、回退路径），中性化后单独发 |
| 采集器 / 清理脚本 / 简历生成器 | 与具体平台 DOM、个人素材强绑定，属于实例侧 |
| 岗位族图谱、简历 HTML、台账数据 | 个人数据，不进公开仓库 |
| `templates/accounts.example.json` 之外的账号配置 | 登录态与账号 id 永不公开 |

因此 clone 下来能跑通「壳 + 导航 + 只读接口 + 兜底」，但**看不到真实数据**。
想看完整链路的效果，按下节自己接一两个页面即可。

## 自检

```bash
# 敏感串扫描（白名单文件零命中才允许发布）
python tools/verify_template.example.py sensitive

# 历史文件 hash 与基线一致（防无意改动）
python tools/verify_template.example.py hash-check <baseline.json>
```

扫描词表 `config/local/sensitive_patterns.json` 是**本地私有**的（gitignored），脚本自身只带 4 条通用正则
（手机号 / 邮箱 / 32 位 hex / API Key）。请按自己的情况重建词表，别把真实值写进仓库。

## 双轨说明

这个仓库是**通用模板轨**（公开，无个人数据）。作者自己的求职工作区是**实例轨**（私有，含账号、简历、台账、调研快照）。
两轨同源：实例轨里改完通用逻辑，按白名单导出到模板轨。这样既能公开代码，又不会泄露正在求职的人的数据。
