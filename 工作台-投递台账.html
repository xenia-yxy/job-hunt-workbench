设计口径
  • 数据源：runs/*/ledger.jsonl，坏行跳过；稳定 ID = 批次 + 行号 + 去重键（job_id 优先，退回「公司|标题」）。
  • 结论口径：outcome 或 delivery.outcome；只有 delivered 计入已投递，与 jkit/store.py 一致。
  • 条件快照：新批次读 summary.json 展示本次实际生效条件 + 目标完成情况（P-B）；旧批次只存路径字符串，仅展示原文，不解析不回填。
  • 判定详情：每行「依据/判定」可展开，显示否决项 / 判定依据 / 评分 / HR 状态 / JD 摘录（P-D）——即"为何跳过、为何投"的详情级留痕。
  • 跟踪主表仍按既有铁律只保留「有沟通、有后续机会」的记录；海投流水不灌进主表，通过可选 source_refs[] 引用式关联。
  • 历史台账与快照一律不回改；条件变更必须新建批次与 condition_id。
